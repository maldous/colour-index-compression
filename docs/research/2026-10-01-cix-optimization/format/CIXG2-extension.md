# CIXG2 extension for adaptive context substreams

CIXG2 is a versioned extension of the CIXG1 framing grammar. The 13-byte
header, per-block route/length/checksum descriptor, end marker, and whole-stream
SHA-256 footer are unchanged; only the five-byte magic changes from `CIXG1` to
`CIXG2` when a CIXG2-only feature is available to or used by the encoder.
Updated Rust and Python decoders accept both magics. CIXG1 archives remain
unchanged and decodable.

The advanced `--format auto` policy currently emits CIXG1 for FAST/DEFAULT and
CIXG2 for BEST automatic search. `--format cixg1` constrains search to the
legacy-compatible candidate subset; requesting coder 6 explicitly with this
format is an error. `--format cixg2` forces the version while retaining route
and coder search. This is version selection within CIXG1's family, not automatic
comparison against CIXM6/CIXF1 packaging.

## New substream coder ID 6

Coder 6 payload is:

```
version:u8 (=1), order:u8 (1..=16), bucket_bits:u8 (1..=8),
unsigned-varint arithmetic_bit_length, arithmetic payload bytes
```

The arithmetic model is the existing adaptive multinomial byte model, with a
context bucket derived from the last `order` bytes. The model count is bounded
to `2^bucket_bits` (at most 256 models). Decoder output length comes from the
existing `<BII>` substream descriptor. Payload byte count must equal
`ceil(arithmetic_bit_length/8)`; unsupported parameters, truncation, excess
bytes, or resource-bound violations are errors.

The current encoder only generates a small bounded subset of these legal
parameters (orders 1/2 and 4/8 bucket bits). Order and bucket parameters are
still serialized so later bounded profiles can add candidates without another
container change. They must be counted as route-search candidates and include
their full descriptor and arithmetic payload in size selection.

## Extended PPM search

CIXG1's ordinary compatibility profile remains within PPM orders 0..=3. CIXG2
BEST may evaluate PPM orders through 8, the existing PPM route's decoder limit.
No PPM syntax changes; order is already self-described by that route. The
version boundary makes archives using newly searched orders explicit to older
CIX implementations whose selector/decoder gate was narrower.

## Compatibility and status

CIXG2 is not ZIP, gzip, or a CIXG1 archive with an unknown coder silently
substituted. A CIXG1-only decoder should reject its magic; an updated decoder
must retain CIXG1 decode support and decode all CIXG2 features it advertises.
Python decoding support is implemented on the isolated reference extension
branch based on frozen Python commit `0d835c98040a197e37b7432f2ec7a8688116dae6`.
The Rust candidate path is experimental pending fresh cross-decode and measured
Dickens qualification. No compression improvement is claimed yet.

## Experimental fixed mixer versions

Legacy mixture payload version 1 remains the native route-9 encoder output and the only mixture version permitted inside CIXG1. The Rust decoder also preserves the earlier experimental version-2 recurrence payload, including its original lookup-after-observe model behavior. Corrected recurrence payloads use version 3 and serialize recurrence configuration version 2 (saturating distance buckets; zero denotes an unseen value). Encoder and decoder use the causal feature returned by the preceding observation. Version 3 is not yet generated by production automatic selection. These new prototypes require CIXG2 when framed as CIXG archives. Circular history storage preserves logical lag order and legacy version-1 bytes.
