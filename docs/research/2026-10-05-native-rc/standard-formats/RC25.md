# RC25 native standard formats

`standard_formats` emits and consumes genuine Gzip, Zlib, raw Deflate,
Bzip2, XZ, Zstd, Brotli, LZ4 frame, and Snappy framed streams. It does not
add a CIX envelope or invoke a Python runtime.

The LZ4 implementation calls the upstream LZ4 frame API. The Snappy
implementation calls upstream raw Snappy for each compressed chunk and writes
the standard framed stream identifier, 24-bit chunk lengths, masked CRC-32C,
and at-most-64-KiB chunks. Its framing rules follow the
[Google Snappy framing specification](https://github.com/google/snappy/blob/main/framing_format.txt).
The pinned SDK headers and libraries are recorded in
`docs/research/2026-10-04-execution/jobs/codec-sdk-provision-v1/provisioned.json`.

All calls reject input above 128 MiB. Before allocating output they admit the
retained input, output limit plus one-byte overflow sentinel, and relevant
native scratch/state against `memory_limit`. Deflate-family encoding uses a
capped writer; XZ and Brotli use providers that calculate a bounded
destination before allocation; Bzip2/Zstd use their native candidate peak
estimate. Decoders reserve only a checked `output_limit + 1` buffer or a
checked bounded native destination.

Decoding requires a complete stream and rejects truncated or trailing data.
Gzip uses buffered source accounting so a decoder read-ahead cannot conceal a
trailing or concatenated member. This API deliberately accepts one stream per
call; concatenated members are not a multiple-member convenience mode.

The native CLI exposes these streams explicitly: `--output-format FORMAT`
writes one of the nine standard streams, while `--input-format FORMAT` is
required for standard-stream decode or test. It never guesses raw Deflate.
This one-shot path shares the CLI's atomic output writer and bounded 128 MiB
input read, but rejects CIX container, route, backend, portfolio, streaming,
history, and block controls. It reads in 64 KiB increments, charges retained
input-buffer capacity to `--memory`, and uses a 1 GiB standard-format default
because Brotli's admitted workspace is 512 MiB before input and output. An
explicit `--memory` remains authoritative. Standard encoding caps output at
the smaller of 128 MiB and input plus 2 MiB; decoding retains a 128 MiB output
cap.
