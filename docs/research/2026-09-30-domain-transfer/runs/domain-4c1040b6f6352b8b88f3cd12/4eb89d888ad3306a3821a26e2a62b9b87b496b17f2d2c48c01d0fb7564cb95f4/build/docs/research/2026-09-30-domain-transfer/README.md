There are 18 initial cells: four molecular, three numeric, three database,
four executable and four volume. Every cell has its own immutable manifest,
input hash, source snapshot, output directory and resource lease. CPU lanes
0/2/4/6 are separate physical cores. Maximum simultaneous leases are four
cores, 12,000,000,000 RAM bytes, 4,000,000,000 temporary bytes and zero swap.
Each cell reserves one core, 3 GB RAM and 1 GB temporary storage. Normal cells
have a combined encode/decode limit of 300 seconds; volume cells have a

## Fixed control and physical accounting

PAQ v216 binary SHA-256:
`4fd7b3e768917a665ee4b91c6df3af1d22f540f7ff5beefe7fec689a8db182cc`.
Every PAQ cell uses `-4 -simd AVX2`, one CPU, empty initial state, identical
`candidate.source.bin` basename, and exactly the same original source bytes
for a given asset. Original controls and candidates both use the paid CIXDOM01
wrapper. Its 30-byte header and canonical variant/source-hash metadata count,
as does the entire PAQ archive or native JXL frame. No selector runs; all
candidates are reported before any selection. Variant-name length differences
are charged. Decoder/program/runtime inventories are separate from archive
bytes; there is no whole-package, prize or deployment-size claim.

Every first comparison, including size losses, runs a separate decoder from
the immutable build with the original and materialized source inaccessible.
The decoder receives only the archive and identified software. SHA-256 and
byte length must match. Encoder timing excludes decoder execution. GNU time
records actual command wall time, CPU time and Max RSS; supervisory elapsed
and sampled cgroup memory/temp high-water are retained separately. One measured
run per cell is exploratory evidence, not a statistically controlled speed
leaderboard. Cache is uncontrolled/warm; unrelated host services remain present.

`domain_research.py` prepares manifests, dispatches through the existing bounded
scheduler, and regenerates `DOMAIN-RESULTS.md` / `domain-report.json`. Legacy
harness filenames do not change the paused Hutter programme. Reuse requires
exact input, pinned settings and artifact rehashes. Source imports must resolve
inside the recorded snapshot, including transitive CIX dependencies.

## Packing audit and attribution

* Molecular: paid flags have at most seven trailing bits; raw choice bytes have
  theoretical slack. PAQ already models these together; no rank coder is forced
  onto a small choice stream before the existing representation is measured.
* Numeric: six bounded precision/flag digits per row are one mixed-radix
  sequence, with known count and charged stream length. On this asset it uses
  16,078 instead of 44,640 raw metadata bytes. The PAQ result may reverse this
  saving because the unpacked digits are highly predictable.
* Database: reused mode-3 remaining-count arithmetic already shares capacity
  within each order stream. Palettes, counts, stream lengths and termination
  are charged. There is no alignment padding to remove in this frame. Separate
  field streams trade context and termination costs; no speculative rank mode
  is required for the first transfer test.
* ELF: the same 155 section IDs use a single paid mixed-radix integer, 95 bytes
  instead of 155 varint bytes. It retains the membership bitmap, section table
  and every unchanged byte. A 60-byte raw recovery does not imply PAQ savings.
* Volume: JXL already shares channel/plane entropy-coding capacity. Native
  bitstream padding and termination cannot simply be deleted. Dimensions,
  non-voxel bytes, CRC and payload lengths are included; no extra rank layer.

Historical Silesia pipeline gains are references, not guarantees for these
inputs. The numerical winner used grouped raw correction IDs before PAQ; the
database winner used remaining-count arithmetic, not rank mode. Molecular,
executable and some other historical paths also changed PAQ version/settings.
The new fixed-PAQ comparisons remove that confound. No pipeline gain here is
automatically attributed to CIX index coding.
