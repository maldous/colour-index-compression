# Linux ARM64 PAQ v215 bridge qualification v1

This prepared, root-scheduled job is the next step after a passing, hash-matched offline relocation receipt supplied through `CIX_ARM64_TOOLCHAIN_RECEIPT`. It cross-builds only the CIX-owned PAQ v215 bridge with the relocated GNU AArch64 C/C++ compiler and sysroot, then exercises its actual C ABI under `qemu-aarch64-static -L <relocated-prefix>/usr/aarch64-linux-gnu`. It does not alter `paq_worker.rs`, enable an ARM64 worker, build Rust, or characterize performance.

The retained upstream source is bound to the complete vendor hash map in [paq-v215-build-v1/source.json](/home/user/src/colour-index-compression/docs/research/2026-10-04-native-rc/jobs/paq-v215-build-v1/source.json). The runner rejects a missing or changed retained snapshot. It copies and hashes the current CIX v215 wrapper into isolated work, so the built wrapper is explicit even if it has legitimately moved on from the historical x64 wrapper snapshot.

`probe.cpp` calls only `cix_paq_v215_process` and `cix_paq_v215_bridge_version` declared by the real bridge header. Each command is a fresh process because the header documents one invocation per worker process. The deterministic fixture is 4,096 bytes: 64 copies of a fixed line plus eight copies of bytes 0–255. The ARM process encodes at PAQ level 1 and a fresh ARM process performs archive-only decode. The retained, already-qualified Linux x64 bridge then decodes the ARM archive; a fresh ARM process decodes the x64 archive. Every decoded file must equal the fixture. These exchange checks establish archive compatibility only; they do not assert matching archive bytes or native throughput.

The existing x64 library/probe must still match the hashes in its passed [qualification receipt](/home/user/src/colour-index-compression/docs/research/2026-10-04-native-rc/jobs/paq-v215-qualification-v2/raw/qualification.json). The new receipt captures retained vendor, x64, toolchain, runner, wrapper, library, probe, fixture, and archive hashes before/after the work. Every spawned command writes exact stdout and stderr log files plus argv, return code, timeout state, and log paths before failure is raised. It reads the ARM probe ELF interpreter and rejects a QEMU runtime root that does not contain it.

The shared release scheduler keeps its 4 GB work ceiling. `run.py` measures the shared work directory with `du -sx -B1` before creating its child and reserves a 128 MB local cap; it rechecks that cap after build. The prepared spec reserves CPUs 8 and 10, 3 GB RAM, and 900 seconds. The spec names the passing v3 relocation receipt. That receipt separately identifies the retained v2 prefix and the host runtime-library directory. CMake configuration/build and the direct compiler probe use that host library path only; QEMU receives an empty host library path. The recipe also passes the v3-required `-B <prefix>/usr/aarch64-linux-gnu/bin` linker search path. It has not been run.
