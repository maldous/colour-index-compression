# Native catalogue and streaming SDK checkpoint

The native library can now construct and restore the retained specialist archive families through explicit installed providers. Ordinary CLI selection and automatic mixed encoding are still missing. This checkpoint does not qualify a release, a benchmark result, or a compression record.

`catalogue-v4` passed its offline all-target check/build, 73 full-engine tests and seven C streaming contract tests. Its installed-provider test was enabled: twelve generated PAQ-backed archive recipes and two JXL recipes restored exactly. Other tests cover raw zlib/XZ/Brotli termination, trailing input, caps, cancellation admission, source-derived catalogue order, raw transform parity, mixed nested archive restoration and malformed framing. A separately requested external-test name matched zero tests; it provides no evidence, and the provider tests above supply the raw codec coverage.

`catalogue-v5` passed a fresh offline check/build, the three dispatch tests, the seven C streaming tests, and relocated shared/static SDK consumers. The enabled dispatch case additionally covered geometry text/palette, hydrogen and filter mode zero. It exercised sixteen specialist recipes (fifteen using PAQ somewhere in their stack, one Brotli-only) plus two JXL image recipes. Each PAQ encode/decode invokes the same compiled CIX executable as a private worker. These are tiny generated compatibility fixtures, not corpus compression measurements. The image provider is the pinned CIX bridge to libjxl 0.12.0.

The C ABI stream consumer was compiled and executed independently after installation and prefix relocation, for both shared and static libraries. The existing independent C buffer and C++ consumers also passed. Fragmented C streaming crosses the 65,536-byte block boundary and checks archive compatibility with the normal native buffer decoder. This interface currently emits independent CIXG1 blocks; full-engine streaming and persistent history are separate open requirements.

The implementation distinguishes binary specialist signatures from ASCII generic envelopes. It preserves PAQ v215/v216 CIXP identifiers and the separate joint-discount/store-state stacks. The volume identity candidate encodes its current input once and compares complete CIXV1 versus equivalent zero-lifting CIXI2 framing around the same payload.

Review found and fixed C stream zero-length null-slice construction and result-buffer overlap; unchecked decoder output-size arithmetic; post-allocation output caps in raw encoders; incorrect PAQ parent/child memory accounting; and an executable identity inverse that could clone an oversized intermediate before rejecting its paid length. Native calls observe cancellation between calls; one-shot codecs are not immediately interruptible. Memory declarations combine bounded CIX buffers and conservative codec estimates, not an enforceable in-process RSS ceiling. PAQ workers use child-only limits after parent reservations.

Failures are preserved: v1 failed compilation on fixture paths, missing test imports and type conversions; v2 retained an unnecessary permission-setting call; v3 passed 72 library checks but its C test loop failed to stop after successful finish following flush. The v4/v5 fixes and source snapshots remain separate immutable identities.

Observed qualification resources (four physical cores, no swap): v4 took 20.61 seconds wall, sampled cgroup high water 1,709,096,960 bytes, tracked temporary high water 3,147,262,131 bytes. V5 took 24.59 seconds wall, sampled high water 1,732,915,200 bytes and tracked temporary high water 3,380,734,751 bytes. Memory samples are lower bounds, not exact peaks; these are test/build costs, not product throughput. Each job reserved a further 20 MB for private tiny PAQ files within the aggregate decimal 4 GB temporary policy.

Remaining work includes ordinary CLI/full-engine selection, bounded scheduling and mixed encoding, remaining historical grid decoders and image providers, full-engine protocol and streaming, standard formats/dictionaries, consumer adapters/platform execution, final quality/Sonar, and clean distribution. The acceptance ledger remains coordinator-owned; no RC item is bulk accepted here. Benchmark and publication holds remain active.

The next action is to complete native selector and historical decoder coverage before qualifying ordinary CLI routing.
