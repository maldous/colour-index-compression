# Local CIX research — 28 September 2026

The local candidate improves physical stream size on a public corpus member and
reduces PPM search time without changing its winning bytes. This is an incremental
research checkpoint, **not a completed corpus gate or a #1 leaderboard claim**.
No GitHub Actions were triggered, used for computation, or modified in this work.

Baseline: `2adc6de05416c1ca99b1a29bbfc9deb956e65229`. All stream comparisons use
the identical level-3 configuration and exact input bytes in separate local
processes. The [machine-readable evidence](2026-09-28-evidence.json) contains input
hashes, codec source hashes, physical byte counts, selected models, encode/decode
times, peak process RSS, package versions, and round-trip results. The source hash
covers sorted `cix/*.py` names and contents. Local archive hashes are observed
provenance, not claimed publisher-supplied checksums.

## Implemented changes

- Added count-vector metadata as byte-substream mode 5 and whole-block mode 20.
  The original sequence payload is reused unchanged. Alternatives compete on
  complete serialized bytes; incumbent candidates remain available.
- Added active/dense residuals around the generic uniform prior `total/alphabet`.
  The prior is derived from decoded metadata, with no file or corpus information.
- Require at least 512 input bytes and 64 incumbent metadata bytes before searching.
  Count-vector integer coders encode at most 255 class bytes, so they cannot
  recursively enter this search. This prevents the previous CPU explosion.
- Fixed duplicate low-bit padding in integer local-logclass candidates: the bit
  writer is finalized once and its result reused.
- Train each ordinary PPM history variant once and clone its initial counts for
  each escape law. Stop losing candidates only when a lower bound from already
  emitted physical bytes cannot beat the incumbent. Preserve search order and
  ties; no heuristic candidate removal was introduced in PPM.
- New streams identify as `CIXM6`. The decoder accepts both `CIXM5` and `CIXM6`.
  Old decoders cannot read the new revision. Existing type-class representations
  and the outer file wrapper remain unchanged.

The added candidates cannot enlarge the local portfolio winner. Whole-codec
heuristic interactions still require empirical regression checks; the results
below are bounded evidence, not a proof over all inputs.

## Discriminating probes and performance

All 29 canonical first-tier members were tested as prefixes of at most 4,096 bytes:
no size regressions; one byte saved on Calgary `trans` and one on Artificial
`random.txt`. These are **prefix probes**, not corpus scores. Four historical
Calgary archive extras were examined during the initial probe but excluded from
the canonical report.

Eight reproducible generated complete streams also had no size regressions:

| Generated case | Original bytes | Baseline stream | New stream |
|---|---:|---:|---:|
| Shuffled balanced 64-symbol alphabet | 8,192 | 6,185 | **6,145** |
| Shuffled balanced 256-symbol alphabet | 8,192 | 8,212 | **8,103** |

Balanced 16-, 37- and 128-symbol cases, biased data, a 32-bit counter and random
256-symbol data retained the incumbent size. Balanced histograms are a diagnostic
case; these results must not be generalized to ordinary incompressible data.

PPM order-4 tests use 4,096 source bytes and 16,384 history bytes, three trials,
alternating exhaustive/bounded execution order. All winners are byte-identical
and round-trip verified. Observed median speedups:

| Probe source | Exhaustive seconds | Bounded seconds | Speedup |
|---|---:|---:|---:|
| `alice29.txt` | 0.736 | 0.606 | 1.22× |
| `kennedy.xls` | 0.838 | 0.665 | 1.26× |
| `geo` | 1.769 | 1.574 | 1.12× |
| `random.txt` | 1.394 | 1.229 | 1.13× |

These are local measurements with other bounded benchmark processes present,
not isolated machine-wide performance guarantees. They do not solve the larger
scaling problem: full CIX runs remain much slower than the reference compressors.

## Reproduce locally

Install with `pip install -e '.[dev,fast-bwt,benchmarks]'` inside `.venv`.
The materialized manifests and detailed working logs are under `results/`.
Create the original source tree from the local Git object, without GitHub compute:

```sh
mkdir -p benchmark-work/baseline-2adc6de
git archive 2adc6de | tar -x -C benchmark-work/baseline-2adc6de
OMP_NUM_THREADS=1 .venv/bin/python -m pytest -q --timeout=45
OMP_NUM_THREADS=1 .venv/bin/python benchmarks/local_compare.py \
  --baseline benchmark-work/baseline-2adc6de \
  --manifest results/corpus-manifest.json --limit 4096 --jobs 4
OMP_NUM_THREADS=1 .venv/bin/python benchmarks/ppm_search_probe.py \
  benchmark-work/canterbury/alice29.txt benchmark-work/canterbury/kennedy.xls \
  benchmark-work/calgary/geo benchmark-work/artificial/random.txt
OMP_NUM_THREADS=1 .venv/bin/python benchmarks/local_references.py
```

`--limit 0` requests complete members. `--timeout` bounds each subprocess;
timeouts are recorded as errors, never scores. Baseline reuse requires matching
input hash, codec source hash, level and scope. The committed evidence JSON also
preserves the manifests if the ignored working results are cleared.
